COMO CONFIGURAR O BANCO DE DADOS (Firebase) — PASSO A PASSO
==============================================================

1) Criar o projeto
   - Acesse https://console.firebase.google.com
   - Clique em "Adicionar projeto", dê um nome (ex: pinheirinho-pelicula)
     e siga o assistente (pode desativar o Google Analytics, não é
     necessário). É gratuito.

2) Ativar o Firestore
   - No menu lateral, clique em "Firestore Database" > "Criar banco de
     dados".
   - Escolha "Iniciar no modo de produção" e a localização mais perto
     de você (ex: southamerica-east1 / São Paulo).

3) Pegar as chaves de configuração
   - Clique no ícone de engrenagem (⚙) > "Configurações do projeto".
   - Em "Seus apps", clique no ícone </> (Web) e registre um app
     (não precisa marcar "Firebase Hosting").
   - Vai aparecer um bloco "firebaseConfig" com apiKey, authDomain,
     projectId, etc. Copie esses valores para o topo do script.js,
     substituindo os textos "COLE_AQUI_SUA_API_KEY" e afins.

4) Configurar as regras de segurança
   - Ainda no Firestore Database, vá na aba "Regras".
   - Apague o conteúdo e cole exatamente isto:

-----------------------------------------------------------------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    match /avaliacoes/{docId} {
      allow read: if true;

      // Só permite CRIAR um documento novo com exatamente um voto:
      // {likes:1, dislikes:0} ou {likes:0, dislikes:1}. Nunca os dois
      // de uma vez, nunca outro valor.
      allow create: if request.resource.data.keys().hasOnly(['likes', 'dislikes'])
                    && request.resource.data.likes is int
                    && request.resource.data.dislikes is int
                    && (
                         (request.resource.data.likes == 1 && request.resource.data.dislikes == 0) ||
                         (request.resource.data.likes == 0 && request.resource.data.dislikes == 1)
                       );

      // Só permite ATUALIZAR em uma das 6 formas de UM clique de voto:
      // dar like, dar deslike, desfazer like, desfazer deslike, ou
      // trocar de um lado pro outro (like->deslike ou deslike->like).
      // Nunca deixa os números ficarem negativos nem mudar mais de 1
      // voto por vez.
      allow update: if request.resource.data.keys().hasOnly(['likes', 'dislikes'])
                    && request.resource.data.likes is int
                    && request.resource.data.dislikes is int
                    && request.resource.data.likes >= 0
                    && request.resource.data.dislikes >= 0
                    && (
                         // deu like (dislikes não muda)
                         (request.resource.data.likes == resource.data.likes + 1 &&
                          request.resource.data.dislikes == resource.data.dislikes) ||
                         // deu deslike (likes não muda)
                         (request.resource.data.dislikes == resource.data.dislikes + 1 &&
                          request.resource.data.likes == resource.data.likes) ||
                         // desfez o like (dislikes não muda)
                         (request.resource.data.likes == resource.data.likes - 1 &&
                          request.resource.data.dislikes == resource.data.dislikes) ||
                         // desfez o deslike (likes não muda)
                         (request.resource.data.dislikes == resource.data.dislikes - 1 &&
                          request.resource.data.likes == resource.data.likes) ||
                         // trocou de deslike pra like
                         (request.resource.data.likes == resource.data.likes + 1 &&
                          request.resource.data.dislikes == resource.data.dislikes - 1) ||
                         // trocou de like pra deslike
                         (request.resource.data.dislikes == resource.data.dislikes + 1 &&
                          request.resource.data.likes == resource.data.likes - 1)
                       );

      allow delete: if false;
    }

    // TODO o catálogo de modelos e adaptações mora aqui — tanto o que
    // já existia (migrado uma vez pela página migrar-dados.html) quanto
    // o que for cadastrado depois pelo painel "Adicionar / editar
    // modelo". Cada documento é um modelo (ex: "iPhone 16e") com sua
    // lista de adaptações compatíveis. O site carrega essa coleção
    // inteira toda vez que a página abre.
    match /modelos/{docId} {
      allow read: if true;

      allow create, update: if request.resource.data.keys().hasOnly(['marca', 'modelo', 'adaptacoes'])
                            && request.resource.data.marca is string
                            && request.resource.data.modelo is string
                            && request.resource.data.adaptacoes is list;

      allow delete: if false;
    }

    // Nega tudo que não seja explicitamente liberado acima (mesma ideia
    // da regra padrão do Firebase, só que agora com as exceções de cima).
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

   - Clique em "Publicar".

O QUE ESSAS REGRAS FAZEM
-------------------------
- Qualquer pessoa pode LER as avaliações e os modelos cadastrados
  (necessário para mostrar o % e a busca na tela).
- Só é possível ESCREVER avaliações incrementando like ou dislike de
  1 em 1 — ninguém consegue, mexendo no navegador, zerar os votos de
  um concorrente ou inflar um número direto.
- Só é possível ESCREVER em "modelos" no formato certo (marca,
  modelo e lista de adaptações) — não dá pra mandar qualquer outra
  coisa pro banco.

LIMITAÇÃO IMPORTANTE SOBRE O PAINEL DE ADMIN (leia com atenção)
-----------------------------------------------------------------
O botão "Adicionar / editar modelo" pede usuário e senha, mas essa
senha é só uma trava simples dentro do script.js (variáveis
ADMIN_USUARIO e ADMIN_SENHA) — ela NÃO é uma autenticação de verdade.
Qualquer pessoa que abrir o código do site (F12) consegue ver essa
senha, e as regras acima também não sabem quem está enviando os
dados, só validam o FORMATO. Ou seja: a senha impede uso por engano
ou por curiosos, mas não impede alguém tecnicamente capaz de escrever
direto no Firestore. Para o uso esperado (a própria loja cadastrando
modelos) isso é suficiente. Se um dia isso virar um problema, a
solução é migrar para Firebase Authentication (login de verdade, com
permissão de escrita só pra quem estiver logado) — posso implementar
depois se precisar.

LIMITAÇÃO IMPORTANTE (leia com atenção)
-----------------------------------------
Como o site não tem login/cadastro de loja, o controle de "só um voto
por loja" é feito salvando um marcador no navegador de quem votou
(localStorage). Isso impede o clique duplo acidental, mas alguém com
conhecimento técnico ainda poderia votar várias vezes limpando os
dados do navegador ou usando o console do desenvolvedor. Para o uso
esperado (algumas lojas parceiras avaliando de boa fé) isso é
suficiente. Se no futuro isso virar um problema (votos suspeitos em
massa), a solução é adicionar um login simples por loja (Firebase
Authentication) — aí dá pra exigir 1 voto por conta, não por
navegador. Posso implementar isso depois se precisar.

CUSTO
-----
O plano gratuito do Firestore (Spark) permite bem mais leituras e
escritas por dia do que uma loja de películas deve gerar. Como agora
o site carrega o catálogo inteiro (uns 450 modelos) do banco toda vez
que a página abre, o número de leituras por dia sobe (1 leitura por
modelo, por visita). Ainda assim, fica bem longe do limite gratuito
pra o tráfego esperado de uma loja. Não deve custar nada, mas se
quiser, é possível acompanhar o uso no painel "Uso e faturamento" do
console do Firebase.

MIGRAÇÃO ÚNICA DO CATÁLOGO (só precisa fazer uma vez)
-------------------------------------------------------
O site enviado junto com este arquivo inclui uma página avulsa,
"migrar-dados.html", que NÃO faz parte do site (não tem link nenhuma
página apontando pra ela) — é só uma ferramenta de uso único pra
subir todo o catálogo que já existia direto no código pro Firestore.

Como usar:
1) Publique as regras acima primeiro (passo 4 lá em cima).
2) Abra o arquivo "migrar-dados.html" no navegador (pode ser
   dando duplo-clique nele mesmo, não precisa estar no ar).
3) Clique em "Alinhar e migrar tudo agora" e aguarde a lista de
   progresso terminar com "✅ Migração concluída com sucesso!".
4) Pronto — pode apagar (ou só guardar de lado) esse arquivo, ele
   não precisa ficar no site nem ser usado de novo, a não ser que
   você queira reimportar o catálogo original do zero no futuro.

O que essa página faz, além de enviar os dados: ela também confere,
modelo por modelo, se toda adaptação está "nos dois sentidos" (se o
modelo A lista o modelo B como adaptação, garante que B também liste
A) — isso corrige automaticamente qualquer inconsistência que já
existisse no catálogo antigo antes de subir tudo pro banco.
